## 读表方式

这是纸序的功能分配建议，不是滴答全端实测矩阵。依据是 [首轮参照证据矩阵](https://github.com/The-Ignorant-Person/todo-app/blob/32521bda5e8e5208b1b49b8b9471c8aaf84f1817/docs/research/paperdo-reference-20261016.md) 和本地 `docs/research/dida-web-observations.md`。未知端若采用下列统一要求，属于用户在 Q1 允许提出的纸序自身预期，必须经过本轮确认；不能改写成已经观察到滴答支持。

“主客户端”逐个指 Web、Windows、macOS、Linux、iPhone、iPad、Android 手机／平板、原生 HarmonyOS 手机／平板。Android 和 HarmonyOS 的手机、平板分别验收；Linux 每个已选发行版／架构分别验收，不能被一列合并成一个测试。

表内“完整操作”指在该客户端完成列出的用户动作，不表示无额度限制、所有角色均获权限、全部离线可用或免费权益已决定。“Web 管理”指可从本客户端清楚进入纸序网页版完成指定操作，不能冒充该端原生完成。没有用“系统不支持”作为统一跳转或删除功能的免责条件。

## Q14 主客户端共同能力

**推荐：下表列出的共同能力在每个主客户端均提供完整操作。** Linux、原生鸿蒙和部分移动布局缺参照实测，统一这些能力是纸序新增的明确要求，而不是以未知推导参照功能一致。付费能力也在交付范围中，具体权益由商业票决定。

| 基线项 | 每个主客户端提供的动作 | 最小验收路径（未执行） |
| --- | --- | --- |
| TASK-01 | 收集箱、快速创建、编辑、完成、撤销完成 | 新建→编辑→关闭重开→完成→撤销；核对同一任务和保存结果 |
| TASK-02 | 文件夹、清单、分组、子任务、移动、排序 | 创建层级→移动任务／子任务→重新排序→重开；归属与数量可核对 |
| TASK-03 | 标签、优先级、智能清单、过滤器、搜索 | 用带／不带日期与标签的任务检验筛选、数量及搜索结果 |
| TASK-04 | 正文、笔记、附件、模板、复制、评论、主任务关联 | 保存重开；模板生成新任务；失败附件不假报成功；按角色显示允许动作 |
| TASK-05 | 放弃／重新开始、删除／恢复、任务和笔记互转 | 每次转换核对已约定字段；恢复后可找到对象；冲突与不可转换项有说明 |
| VIEW-01 | 列表、看板、时间线 | 同一批任务切换视图；拖动后任务状态／分组／时间符合领域契约 |
| DATE-01 | 年、月、周、日、日程、多日、多周七个日历入口；安排与调整任务日期 | 同一数据逐视图核对；跨日／无日期任务有确定展示；触摸和键鼠均有可用操作路径 |
| DATE-02 | 公历重复、月末／闰年、完成后重复、农历、工作日／节假日、艾宾浩斯重复 | 每类建立代表与边界场景；完成／跳过后的下一实例按领域票规则判断 |
| TOOL-01 | 四象限查看、调整与设置 | 任务在象限和清单间保持一致，分类变化可核对 |
| TOOL-02 | 专注启动／暂停／结束、记录、统计 | 正常与中断场景各一条；记录能被复核，跨端计时语义待领域票定案 |
| TOOL-03 | 习惯和纪念日的创建／编辑／记录／修正／统计 | 跨日、补记和日期边界场景结果一致 |
| SHARE-01 | 邀请／接受、成员管理、角色、指派、评论、退出与撤权入口 | 两账号验证允许及拒绝路径；被撤权后不能继续得到未授权内容 |
| BRAND-01 | 纸序主题、浅色／深色与清单背景；用户偏好 | 主要状态可读；切换后保存；具体视觉和无障碍数值由对应票决定 |

七个日历入口来自既有 Web 入口观察，并未完成会员真实交互。**选择七个是纸序范围决定**，不能用“6 种视图”的旧文案删掉第七项；各端布局可以不同。上表不顺带要求各端都有位置提醒、持续提醒、系统插件或同样的 AI 输入入口，这些在 Q15 分配。

| 持续提醒 | 本轮不新增持续提醒机制 | 本轮不新增持续提醒机制 | 原生移动端提供 | 原生移动端提供 |

| AI 助手 | 主动触发、审阅后使用 | 同左 | 同左 | 同左 |

注意：

- 本地模式和登录后离线编辑是两个入口。云 AI、共享成员管理、购买等需要联网的动作不因“离线编辑”自动变成离线承诺；已保存内容与待同步状态必须可理解。
- 迁移的 Web 集中管理只涵盖整套备份和六类来源迁移，不限制普通任务附件在各客户端打开、保存或上传。其他端原生备份工具是否必要，是这次明确的取舍；不是已确认事实。
- 账号渠道的第三方服务商、实际资格和费用在对应票确定；本表冻结正常注册／登录／恢复／安全管理旅程，不用虚假的按钮替代可用流程。
- 官方资料已有清单动态电脑端声明；任务历史与清单动态分开。动态的手机跳转是本次提案；不把全部历史操作都改成 Web。
- AI 助手和录音转写／总结统一到主客户端是纸序要求；此前没有逐端实测证明。遵守已确认的主动触发、只发送所需数据、不默认扫描全部任务、不用于训练约定。
- 位置提醒、持续提醒与语音添加按端分配具有参照声明依据，但本表不能证明其他端在参照中一定不存在。用户若需要更多端，应在本轮改表。

### 官网、订阅与运营旅程不变

穿戴动作的依据边界：[中国版官方手表文章](https://help.dida365.com/external/articles/7069931247773941760)泛称今天／最近七天、添加、习惯打卡、同步和振动，页面元数据为 2023-07-05，未逐华为／小米型号划分；其 Apple Watch 专注说明也有设备间提醒和关联任务限制。[当前小组件说明](https://help.dida365.com/articles/6950366960659988480)明确 Apple Watch 任务／习惯组件可完成／打卡。它们支持提出纸序目标，不构成所选每个型号已实测或当前上架可用的证明。

邮件宿主的依据边界：中国下载中心指向的 [Google 插件条目](https://gsuite.google.com/marketplace/app/appname/1046514147108)详情本轮未能读取；同一 ID 的 [发布者 2020 年介绍](https://blog.ticktick.com/2020/06/03/handle-inbox-with-ticktick-for-gmail/)泛称桌面和移动可用，不能替代当前 Android／iOS 或中国版账号授权验证。[Microsoft 商店条目](https://marketplace.microsoft.com/en-in/product/office/WA200003699?tab=Overview)说明邮件转任务，未列逐宿主支持；中国帮助有 Outlook 入口，但未建立当前下载页至该商店项的完整链路。因此上表选择全宿主是明确的纸序目标建议，不是宣称参照已逐端覆盖。宿主版本、账号类型、地区、实际授权和分发路径仍须形成验证配置；任何受限组合须有证据并回到范围决策，不能暗中跳过。

官网／下载、注册登录、帮助、更新、媒体素材、教育优惠、礼品卡、订阅／订单／退款／发票／支持和必要运营后台已纳入。具体页面与流程仍须有效，不能以“有页面”代替可办理。各应用提供对应入口；商店支付、外部支付跳转及权益管理方式由已存在的主体／渠道和商业票决定，不在这里提前绕过或承诺某种渠道规则。

## 范围票收束检查

Q14–Q16 通过后，可把这些功能分配作为范围决定候选整理为最终审阅版，但必须区分三类事项：

| 类型 | 处理方式 |
| --- | --- |
| 仍会改变交付范围的选择 | 如某邮件宿主是否交付、手表是否能创建／完成、某日历是否写回，必须补证并明确决定，不能作为一般测试细节掩盖 |
| 已定目标的运行验证配置 | 如发行版镜像校验值、用于复现的具体补丁号、测试手机应用版本，可以随验收方案锁定；没有这些就不能声称已验收，但无需反复询问是否纳入已选系统族 |
| 已有后续票负责的契约 | 重复计算、恢复期限、角色权限、冲突、迁移字段、价格／额度、组件／算法、时延／性能数值，留给相应票；最终规格票检查全部闭合 |

主端共同能力、Web 跳转及配套动作已确认；[范围收尾提案](scope-final-proposal.md)中的穿戴额外动作、小组件模块、日历读写、导入路径和例外处理也已接受。具体配对、样本、宿主能力及学校名单由 [支持证据核实](https://github.com/The-Ignorant-Person/todo-app/issues/14) 和 [支持名单审定](https://github.com/The-Ignorant-Person/todo-app/issues/15) 承接，不能因范围目标批准而标记已完成。

## 用例记录格式

每个用例记录：能力 ID、平台／设备、已批准支持范围、前置账号／数据／权限、动作、预期结果、参照证据状态、纸序决定链接、验证方法、实际结果与证据。

示例（仅计划，未执行）：`TASK-01-ANDROID`，Android 8/API26 ARM32、合成普通账号；离线新建任务→修改标题→重启客户端→联网；预期重启后本地数据仍存在、显示同步状态、联网后另一已登录主客户端出现同一任务；同步时限与冲突细节由领域／质量票补齐。此示例不证明 Android 8、ARM32 或任何客户端已经可用。
